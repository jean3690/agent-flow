# 执行期限、事件缓冲与过载保护

本轮保护范围是单实例内的上游连接、SSE 读取和 Python 事件缓冲，不是硬实时任务系统，也不是完整的等待式背压。

## 1. 平台服务 固定上游期限

同步 `/run`、SSE `/execute`、Cron 和 Webhook 共用以下规则：

- 执行任务**出队开始连接 Python 时**启动单调时钟期限。
- 期限为 Python 有效 `options.timeoutMs` + `EXECUTION_TRANSPORT_GRACE_MS`（默认 5000ms）。它不会因 token、日志或心跳到达而重置。
- 用户 `timeoutMs` 必须在 1–3600000ms；默认 120000ms。根图及内联子图的人工审批会为最长等待保留 30 秒缓冲，再叠加 平台服务 读取宽限。
- 响应头等待使用可取消的 HTTP future；body 读取由独立期限线程关闭 InputStream 解阻塞，不把期限任务排进执行线程池。
- 到达 `run_finished` / `run_failed` 即停止读取，不等待 `done` 或上游 EOF。资源释放后再进行原有事务收尾和客户端终态发布。
- 超时记为 FAILED，未结束节点一并 FAILED；平台服务 合成 SSE 错误码 `RUN_TIMEOUT`。用户取消仍为 CANCELED，排队取消不向 Python 提交。取消通知异步发送，不等待错误响应 body。
- 完成时移除期限任务；取消和响应到达竞态中的迟到 body 也被关闭。

`AI_SERVICE_TIMEOUT_MS` 仍是 AiClient 请求配置，并不单独代表流式 body 总期限。工作流读流的绝对期限由 `ExecutionControl` 负责。

### 仍不覆盖的阻塞

期限不含请求准备、执行线程池排队、最终数据库事务或向浏览器写 SSE 的耗时。它会关闭上游连接，但**不能保证解除卡在数据库或客户端 socket 写入中的线程**，也不能抢占 Python 同步 CPU 代码。部署仍需数据库连接/语句超时、代理写入/空闲超时和 CPU/内存限制；不能宣称整个 HTTP 请求严格在 timeoutMs 内返回。

## 2. 平台服务 SSE 大小边界

`app/sse.py` 逐行读取并累计大小：无换行长行也会在上限处失败，多个 data 行按一个事件累计检查。默认 `EXECUTION_MAX_EVENT_CHARS=2000000`，单位是解码后的 Unicode 字符，不是 UTF-8 字节。每行（包括心跳行）也受相同上限限制。

保留 UTF-8、BOM、LF/CRLF/CR、多行 data 和无末尾空行的兼容行为。超限使执行失败并关闭上游，不尝试解析部分 JSON 或继续读取。

## 3. Python 有界事件缓冲

`EventBus` 在入队时序列化 SSE，限制：

| 配置 | 默认值 | 用途 |
| --- | --- | --- |
| `AI_EVENT_BUFFER_MAX_EVENTS` | 256 | 普通事件最大积压数 |
| `AI_EVENT_BUFFER_MAX_BYTES` | 4194304 | 普通事件积压的 UTF-8 字节数 |
| `AI_EVENT_MAX_BYTES` | 1048576 | 单事件大小，包含 SSE/JSON 元数据 |
| `AI_EVENT_HEARTBEAT_SECONDS` | 15 | 空闲流发送注释心跳的间隔 |
| `AI_MAX_CONCURRENCY` | 8 | 同时保留的执行/响应流名额 |

正数、字节下限和心跳范围在配置加载时校验。普通队列之外预留两个终态事件和一个关闭标记的位置，因此普通缓冲满了也能发出失败与 done；正常终态同样使用预留空间。终态数据仍受单事件限制，done 固定为小型协议标记。

生产接口目前是同步 `emit`，所以策略是**超限中断，而不是 await 等待腾位**：

- 已接纳的进度按顺序保留，不静默丢弃 token。
- 单事件过大产生 `EVENT_TOO_LARGE`，积压过多产生 `EVENT_BUFFER_OVERFLOW`；随后发送 done 并关闭缓冲。
- 使用不会被节点普通重试/失败继续吞掉的内部中断信号，避免资源耗尽后继续产生副作用。
- 空闲时发送 `: keep-alive` 注释，不占队列、不作为业务事件、不延长 平台服务 截止时间。
- 终态之后忽略迟到生产事件，避免成功后再因 done 入队失败生成矛盾的失败事件。

这些限制约束**待发送的序列化事件**，不是整个进程内存上限；图状态、节点返回值、序列化瞬时分配及 ASGI/操作系统网络缓冲仍需另外评估。终态预留字节也应计入容量预算。持续慢客户端可能占用响应名额，需配合反向代理连接超时。

## 4. AI 执行准入与取消

Python 超过 `AI_MAX_CONCURRENCY` 返回 503，不创建新 runner；未释放的同 runId 返回 409，不能覆盖原取消句柄。名额直到响应流 finally 清理后释放，包含“运行完成但缓冲尚未排空”的响应。`runId` 可省略，但显式传入时必须为 1–64 字符。

平台线程池容量和 AI 准入容量是两层独立边界。若平台服务同时派发超过 Python 名额，Python 会拒绝，已建立的平台执行返回 FAILED；这不同于 平台线程池拒绝时直接返回 HTTP 503。不要用无限队列隐藏过载，应按真实模型耗时和限制调参。

客户端关闭 平台服务 SSE 仍不等于取消后台执行；显式取消走 cancel 接口。平台服务关闭上游会触发 Python 流清理，取消尚未完成的 runner 并释放进程内登记。

## 5. 验证与指标

`agentflow.execution.transport.timeouts` 统计平台上游期限超时；现有活动线程、等待队列、执行状态和持久化失败指标继续保留。

回归覆盖：真实 HTTP 客户端 + 本机隔离 HTTP 上游的响应头/阻塞 body/不结束错误 body、全部执行入口的超时收尾、取消竞态、无 EOF 终态、SSE 大小限制、UTF-8 字节预算、关闭预留空间、心跳、准入恢复及小于一秒的运行超时。用例通过不代表真实模型容量或高可用能力。
