# 文件用户隔离与私有预览

文件中心、文件 IO 节点、图像/视频/TTS/图片翻译产物统一使用用户目录；所有下载都需鉴权，不提供匿名或永久分享链接。历史文件不自动移动、归属猜测或删除。

## 1. 两层权限边界

**平台服务对外**：`/api/files` 的上传、列表、读写、下载、删除均通过 JWT 或 `X-API-Key` 认证。`FileService` 从已认证用户上下文选择存储身份，不转发浏览器伪造的 `X-Storage-User-Id` / `X-Storage-Legacy`。

- 无凭证或失效凭证返回 401。
- 普通用户只能选择本人目录，跨用户及历史共享区访问统一返回 404。
- 管理员可通过显式用户路径/列表参数访问其他用户目录；默认列表仍只显示本人文件。
- API Key 使用其拥有者的用户 ID 与角色。管理员 Key 仍是高权限凭据，不应视为只读文件 Key。

**Python 内部**：所有 `/v1/files*` 与 `/files/*` 路由需 `X-Internal-Token`，并由服务端上下文选择用户。执行和取消接口也统一要求内部令牌，不能公开提交伪造的 userId 来读取其他用户文件。健康检查、节点目录和纯图校验不等于执行权限。

内部令牌代表可信平台服务，可选择用户或历史区，权限高于普通用户凭证。必须替换默认值、保持平台服务/AI 一致并限制 AI 服务网络可达性；不要将内部令牌给浏览器、普通 SDK 客户端或远程工具服务器。

## 2. 存储布局与引用

配置项仍为 `AI_FILE_DIR` 和 `AI_OUTPUT_DIR`，前者为空时回退后者。新文件位于：

```text
AI_FILE_DIR/.users/{userId}/reports/today.txt
AI_OUTPUT_DIR/.users/{userId}/{随机媒体文件名}.png
```

对外元数据的 `path` / `name` 保留用户目录内的相对路径，如 `reports/today.txt`；`url` 明确标识用户，形如 `/files/users/1/reports/today.txt`。SDK 访问平台服务 时使用 `/api/files/...` 并携带鉴权。

```bash
# 本人相对路径；服务器根据凭证选择用户。
curl -H "Authorization: Bearer $TOKEN" \
  http://localhost:8084/api/files/reports/today.txt

# 明确用户的资源引用；普通用户跨用户访问会返回 404。
curl -H "X-API-Key: $API_KEY" \
  http://localhost:8084/api/files/users/1/reports/today.txt
```

`users/`、`legacy/` 和物理 `.users` 为保留命名空间。拒绝越界路径、设备/控制字符及符号链接；列表也不会跟随符号链接或暴露其外部目标元数据。文件与媒体目录同名时仍优先文件目录，媒体采用随机文件名减少冲突；这不构成内容版本不可变保证。

## 3. 工作流与媒体

- 文件节点仍可配置 `reports/{{input.date}}.txt` 这样的相对路径，但只在执行用户目录内读写。
- 子工作流和 foreach 继承用户上下文；缺少有效用户 ID 的文件或媒体操作失败，不回退到共享目录。
- 存储辅助函数本身也拒绝未绑定的全局 Settings；新增节点忘记绑定用户时失败，而不是意外读写共享根。
- 图像、视频、TTS、图片翻译输出使用同一隔离规则；视觉理解和模型本地参考图只能读取执行用户文件。真实调用所需本地图片转换为 data URL 或上传至厂商临时存储，而非公开本地下载 URL。
- 管理员运行工作流时，文件节点也按执行用户身份隔离，不自动获得跨用户文件读取特权。管理员跨用户文件管理需要显式使用文件 API。
- 存储策略已纳入 `v2:` 执行指纹；旧 `v1` 续跑请求返回 409，需要完整重跑。此升级不新增数据库字段。

## 4. 浏览器预览与下载

`img/audio/video` 标签无法附带普通 Authorization 头，因此前端先对**可信平台文件地址**发带 JWT 的请求，再通过 Blob URL 预览或下载：

- JWT 不放进查询参数、持久化输出或可复制的文件 URL。
- 远程图片/媒体仍直接使用远程地址，不会收到平台 JWT；辅助函数拒绝向外站伪装的 `/api/files` 地址发送凭证。
- 输出变化、关闭预览或离开页面时中止旧请求、释放 Blob URL；离开文件中心也会中止未完成下载。
- 401 按登录失效处理；404 不会退回匿名下载重试。
- 文件响应使用 `private, no-store`、`nosniff` 和 sandbox CSP；HTML/XML/SVG/脚本类型作为附件，不提供活动内容在线执行。SVG 文件不在图片预览列表中。

当前 平台服务下载与前端 Blob 会读取完整文件，并未实现流式下载、Range 或配额。大媒体需继续评估内存和容量，不能将这轮权限隔离视为大文件服务性能优化。已授权客户端取得的副本无法通过退出登录或吊销凭证追回。

## 5. 历史共享文件

旧根目录中的文件保持原样，不自动归属给任何用户。管理员可以通过以下只读入口处理：

```text
GET /api/files?legacy=true
GET /api/files/legacy/{历史相对路径}
```

历史区列表排除 `.users`，不允许写入、追加或删除。确认归属后，应使用目标用户凭证重新上传到用户目录，必要时更新旧绝对引用；纯相对路径可在重新导入同路径后继续使用。

旧匿名分享 URL 不再可用，旧执行的未分区媒体引用也不会自动映射到历史区。管理员需显式读取历史地址，普通用户需重新导入，避免静默泄露他人旧数据。

备份/恢复应协调业务数据库与文件卷，避免重建用户表导致 ID 复用后将旧用户目录分配给新身份。

## 6. 未提供的保证

这是应用层用户命名空间，不是独立 OS 用户、容器或文件系统沙箱；无法抵御已获得主机权限的攻击者或所有本地替换竞态。模型配置仍为平台共享，未实现用户配额、每文件 ACL、文件版本/生命周期、审计、对象存储、共享链接或跨实例存储一致性。

回归使用隔离临时目录、SQLite 内存库、本机 HTTP 上游和 mock 浏览器 API；覆盖同名文件隔离、伪造身份、匿名访问、API Key 吊销、路径/符号链接、子图文件归属、媒体与 Blob 生命周期，不接触本地持久化业务数据。
